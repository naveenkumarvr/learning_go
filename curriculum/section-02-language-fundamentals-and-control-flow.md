# Section 02: Language Fundamentals and Control Flow

**Stage:** Stage 1 — Go Foundations

## Purpose
Write idiomatic Go with clear control flow, explicit types, and predictable behavior.

## Prerequisites
- Prior sections or an equivalent demonstrated baseline.
- A working Go toolchain and ability to run tests locally.
- Relevant DevOps knowledge may be assumed when the section connects to cloud-native systems; focus on Go implementation and engineering judgment.

## Topics
1. **Declarations, constants and scope** — Use var, :=, const, zero values, shadowing, and lexical scope correctly.
2. **Primitive types and conversions** — Work with booleans, strings, numeric types, explicit conversions, and overflow boundaries.
3. **Operators and control flow** — Use if, switch, for, range, labels only when justified, and early returns.
4. **Strings, runes and Unicode** — Distinguish bytes, runes, grapheme clusters, and safe string processing.
5. **Input, output and formatting** — Use fmt, bufio, strings, strconv, and robust input parsing.
6. **Basic algorithmic reasoning** — Estimate time/space complexity and choose straightforward solutions before optimizing.

## Expected outcomes
- Explain and apply declarations, constants and scope in idiomatic Go.
- Explain and apply primitive types and conversions in idiomatic Go.
- Explain and apply operators and control flow in idiomatic Go.
- Explain and apply strings, runes and unicode in idiomatic Go.
- Select and explain an appropriate design, including trade-offs and alternatives.
- Demonstrate behavior through tests and reproducible commands.
- Diagnose failures using evidence rather than guessing.
- Explain where the techniques apply in production and when a simpler approach is preferable.

## Learning workflow
For each topic, work through its three projects in order unless the instructor and validator agree that existing evidence supports skipping a project. Do not skip validation solely because the code compiles.

## Section capstones
Complete the three capstones under `projects/section-capstones/section-02/`. They integrate multiple topics from this section and at least one earlier concept where useful.

## Exit criteria
- Topic projects required by the learner's plan have objective validation evidence.
- The learner can explain the core mental models and key trade-offs without relying on memorized definitions.
- All three section capstones meet mandatory acceptance criteria or have explicitly documented exceptions approved by the learner.
