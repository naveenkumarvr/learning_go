# Project Specification Standard

Every project specification must state:
- Problem and intended outcome
- User story / operating scenario
- Concepts practiced
- Requirements and non-goals
- Milestones
- Architecture and data/control flow (Mermaid is encouraged when it clarifies design)
- Why the design fits, alternatives, and trade-offs
- Real-world relevance: when to use and when to avoid the pattern
- Required tests and failure cases
- Objective acceptance criteria
- What the learner must submit
- Relevant primary and secondary resources

Prefer official Go documentation and focused references. Do not require paid resources when a suitable free resource exists. Projects should be runnable locally unless cloud-specific behavior is the actual learning objective.
